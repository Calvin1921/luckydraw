# Lucky Draw MVP — Security Review

> Date: 2026-04-07
> Document reviewed: `luckydraw/ARCHITECTURE.md` (as of 2026-04-07)

---

## Verdict: APPROVED WITH CONDITIONS

The architecture is sound in its design intent. All four CRITICAL findings from the threat model are correctly captured and classified in the Security Model section of ARCHITECTURE.md. The document clearly marks them as "must fix before any development proceeds" — this is the right disposition.

## What Is Confirmed Correct

**Draw integrity:** `crypto.getRandomValues()` runs server-side in a Convex mutation. The client cannot influence winner selection. The seed is logged post-draw for audit. Algorithm version is stored. `Math.random()` is not used. **APPROVED.**

**Stripe webhook:** Signature verification via `stripe.webhooks.constructEvent` is present. Raw body is used (not parsed JSON). Returns 400 on failure. `activateLicense` is correctly specified as `internalMutation` in the API contract — this is the right fix for REQ-02. **APPROVED.**

**Clerk + Convex auth bridge:** `auth.config.ts` pattern, `ConvexProviderWithClerk`, middleware route protection are all correctly designed. Token storage is SDK-managed (no localStorage). Session cookie is httpOnly. **APPROVED.**

**`getSession` PII projection:** The API contract for `draw.getSession` now specifies `winner: { _id, name, nameZh } | null` — email and phone are excluded. `remoteToken` exclusion from public query responses is called out in the SECURITY condition. **APPROVED WITH IMPLEMENTATION VERIFICATION.**

**`ensureOrg` server-side identity:** The API contract now specifies clerkOrgId must come from `ctx.auth.getUserIdentity()`, not from args. **APPROVED WITH IMPLEMENTATION VERIFICATION.**

**Audit trail:** `winnerLogs` is append-only with no exposed update/delete mutations. `_creationTime` is system-generated. Denormalized fields make records self-contained. PDPO retention concern addressed by the HIGH condition on soft-delete. **APPROVED.**

**Environment variable placement:** The document correctly distinguishes `NEXT_PUBLIC_*` (safe for client bundle) from server-only secrets. The instruction to set Stripe and Clerk secrets in Convex dashboard (not `.env.local`) is correct. **APPROVED.**

**CSPRNG modulo bias:** Documented correctly — for ≤300 participants, bias is ~0.000007%. Acceptable. **APPROVED.**

## Conditions That Must Be Met Before Production

These conditions are already listed in ARCHITECTURE.md. This review confirms they are mandatory and non-negotiable.

### CRITICAL (block implementation start)

**C1 — REQ-01: `assertOrgOwnership()` in every mutation**
All write mutations that take `eventId`, `orgId`, `participantId`, `tierId`, `prizeId`, or `sessionId` MUST call `ctx.auth.getUserIdentity()` and verify the resource belongs to the caller's org. A shared `assertOrgOwnership(ctx, eventId)` helper should be used consistently. This is the most exploitable vulnerability in the current plan.

**C2 — REQ-02: `activateLicense` as `internalMutation`**
The API contract correctly specifies `internalMutation`. The implementation must follow this — any deviation to `mutation()` is a shipping blocker.

**C3 — REQ-05: `getSession` PII projection**
Implementation must strip email, phone, importSource, and isEligible from winner data before returning to unauthenticated screens. Also: `remoteToken` must be stripped from all query responses going to stage and audience pages — it must only be returned when the authenticated operator creates the session.

**C4 — REQ-06: CSV export authentication**
`/export/winners` MUST require auth before any real participant data is stored in the system. Signed short-lived tokens (generated by an authenticated mutation, validated in the HTTP action) is the recommended pattern.

### HIGH (fix during development, before QA)

**H1 — REQ-13: `ensureOrg` client arg removal**
Implementation must remove `clerkOrgId` from mutation args. Already documented in the API contract.

**H2 — REQ-03: `remoteToken` verification in draw mutations**
`triggerDraw`, `confirmWinner`, and `rejectWinner` must accept `remoteToken: v.string()` and verify it against `session.remoteToken` before executing.

**H3 — Soft-delete for events**
`events.remove` must not cascade-delete `winnerLogs`. A soft-delete with `archivedAt` timestamp preserves the audit trail required by PDPO.

**H4 — REQ-04: `actorUserId` from `ctx.auth`**
Remove from mutation args. Derive server-side.

## One Discrepancy to Correct

The Security Model threat table (line 723) lists "CSV injection" as **Low risk** with the note: "CSV export wraps all cells in quotes and escapes internal quotes. No formula injection risk."

**This is incorrect.** Quoting and escaping internal quotes does NOT prevent CSV formula injection. Excel and Google Sheets evaluate formulas in quoted cells — a participant named `=HYPERLINK("http://evil.com","click")` will execute when the organizer opens the export, regardless of surrounding quotes.

The document contradicts itself: MEDIUM condition #12 correctly calls for sanitizing leading `=`, `+`, `-`, `@` characters. The threat table entry should be updated to reflect MEDIUM risk (not Low) with "partial mitigation." This is a documentation fix, not an architecture change.
